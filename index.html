Capabilities

A design studio with an engineering core.

The strongest engagements are systems with unusual state, timing, media, simulation, hardware or information-model constraints—places where interaction design and architecture cannot be separated.

01

Product and system architecture

Clarify the domain, ownership, authority and lifecycle before UI complexity hardens around accidental implementation details.

02

Interaction and prototyping

Build working experiments early enough to test spatial behavior, timing, transitions, feedback and physical or media interaction.

03

Native web experiences

Use semantic HTML, modern CSS, View Transitions, Web Animations and progressive enhancement before adding runtime abstraction that the platform already provides.

04

Engineering and verification

Turn successful experiments into durable systems with strict types, deterministic tests, performance evidence, accessibility checks and CI-backed browser certification.

Approach

Explore freely. Promote evidence. Encode the result.

The studio process deliberately separates discovery from commitment. A fast experiment can stay cheap; a behavior only becomes architectural once there is enough evidence to protect it.

01

Model the problem

Map actors, constraints, states and failure modes. Make ownership explicit before selecting a presentation architecture.

02

Prototype the behavior

Use playable software, real media, real hardware and representative data to test the interaction rather than only describing it.

03

Harden what survives

Move proven behavior into types, tests, contracts, CI and documentation so later iteration can remain fast without losing the model.

Professional thread

Design practice informs the way I engineer software.

My background connects graphic design, multimedia production and teaching with public-service software, large planning interfaces and systems engineering. Code is a design material: a way to clarify relationships, test assumptions and shape interaction.

The through-line is not a particular framework. It is the ability to move between visual composition, user observation, state modeling, implementation, performance analysis and verification without treating those disciplines as separate handoffs.
