Vial / Halcyon

A control layer for the Halcyon Ferris that connects Vial configuration, telemetry and persistent TFT settings to real firmware through an explicit protocol without turning the standard Vial path into a one-device application.

System view

Firmware↔Raw HID protocol↔Vial control center

The niche

Custom firmware often evolves faster than the generic interface used to configure it.

The Control Center occupies that gap: it preserves the normal Vial workflow for standard devices and presents extra controls only when the connected keyboard implements the corresponding Halcyon protocol.

What is different

The product is designed on both sides of the USB cable.

Firmware–host contract

A typed Raw HID protocol carries persistent settings and telemetry instead of relying on implicit UI assumptions.

Live TFT editing

Palette, cadence and style can be changed from the host and reflected at runtime without recompiling firmware.

Visible semantics

Combos, tap dance, encoder pairs and RGB profiles are presented as understandable behavior rather than opaque data.

Verifiable web delivery

Vial Web pins a concrete GUI revision, validates the package and publishes the Control Center as a reproducible web tool.

Product & design thinking

Specialization appears as capability, not as a total product fork.

The interface uses controls suited to each data type and groups hardware-specific features under a coherent Halcyon surface. A standard device does not need to know those controls exist, while a compatible device should not require the user to edit raw values without context.

Geometry and telemetry also reduce the distance between what the user sees and what the hardware does, turning configuration into a tool for understanding as well as editing.

Development approach

The creative loop crosses the USB cable: change the physical behavior, expose it visibly, try it on the real keyboard, then turn the useful discoveries into a stable protocol.

Firmware owns persistence and runtime behavior; the GUI owns editing and validation; Vial Web owns packaging and deployment. Keeping those responsibilities separate makes experimentation safer: a display animation or interaction idea can evolve quickly without making the transport contract ambiguous.

This replaces the traditional sequence of firmware change → bespoke debug build → manual verification with a tighter cycle of live telemetry, capability-aware controls and repeatable host-side checks. The discipline is what makes room for tactile experimentation with color, timing, geometry and input behavior.
